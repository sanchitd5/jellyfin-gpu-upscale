Skip unless the target height is at least this multiple of the source height.
Run the super-resolution network only at or above this ratio. Below it the upscale still happens, with plain scaling plus whatever unblur is selected, and the network's GPU time is not spent. 0 disables the bypass.

Both shipped networks are fixed 2x, so below 2x their output is shrunk back down. Measured against a clean ground truth, FSRCNNX's detail advantage over plain scaling is -2.2% at 1.41x, -0.3% at 1.50x, +3.6% at 1.70x, +7.2% at 1.90x and +19.3% at 2.00x: the crossover is about 1.52 and the network costs ~15% of throughput. The default of 1.60 therefore keeps 720p to 1080p (exactly 1.5x, and a large share of real sessions) on plain scaling. Unblur is what fills the detail in at those ratios, at about 1% of the cost: at 1.5x, plain scaling plus RCAS 2.0 measured detail energy 3.5950 against a ground truth of 3.5179, where the network alone managed 3.2726.

Default levels and what players may use

Each level applies when a session does not pick its own. The Allow box beside it is a master switch for that enhancement.

Used when a playback session does not pick its own shader. Two different networks are offered, not one quality ladder, because which looks right on this content is a matter for the eye rather than for a benchmark.

FSRCNNX is the default. It is the light 8-weight, deliberately: the old "Standard" tier was the 16-weight, which measured LOWER real-footage detail at roughly double the GPU cost, so the 8-weight now carries the plain family name. FSRCNNX was the only shader that raised detail above plain scaling at BOTH scale ratios tested (2.0x and 1.5x) on real captures.

Anime4K M is a generic 2x CNN upscaler despite the name - the anime-specific work in that family is in the Restore shaders, which are not installed. At its native 2.0x (540p to 1080p) it ties FSRCNNX. But at 1.5x (720p to 1080p) it fell BELOW plain ewa_lanczos on every source tested: off its native ratio it softens rather than reconstructs, and on skin it flattens texture into a slightly waxy look. Its weights were trained on animation. Try it and judge by eye - if your sources are mostly 540p it is a genuine alternative.

A sixth level, fsrcnnx-max (FSRCNN_x2_r1_32-0-2), is installed and accepted by the API but not offered here: it measured no better again at about twice the cost. The old names light, standard and max are still accepted by the API and map onto this ladder.
Master switch. When off, no playback session can turn unblur on.
AMD FidelityFX RCAS (FSR v1.0.2, MIT, mpv port by agyild), derived at install time by shaders/install-shaders.sh. It replaced this project's own CAS build after measurement: against a clean ground truth RCAS was better on PSNR and SSIM at both 1.5x and 2.0x, and its detail energy landed 5-10% above ground truth where CAS landed 19-63% above - that gap is over-sharpening. It is also nearly free, because RCAS hooks LUMA and so runs at the network's output size rather than at full output size.

The RCAS sharpness scale is inverted and clamped. 0.0 is maximum sharpening, larger is gentler, and anything above 2.0 is silently identical to 2.0. Gentle/Medium/Strong here read in the normal direction; the inversion is handled in the level mapping, not by you.

The old CAS shaders stay installed and are still reachable by the API under cas-low, cas-medium and cas-high as a rollback path. They are not offered here or in the player menu.
Master switch. When off, no playback session can turn denoise on.
Runs before the upscale, so the network is not asked to reconstruct noise into detail. Light is atadenoise (temporal, CPU); Strong and Max are nlmeans_vulkan, which recovered 46% and 53% of the structural damage noise had done to a visibly noisy source.

OIDN is advanced, and slow. Intel Open Image Denoise, run through a separate patched ffmpeg build that only sessions choosing this level ever touch - no other playback goes near it. On a genuinely grainy high-bitrate source it is by far the best denoiser measured here (74-86% of the fidelity lost to noise recovered, against 34-53% for nlmeans and 4-6% for atadenoise, with no over-smoothing). On this library\'s normal material it measures as a no-op: within 0.01 dB of doing nothing. It is not in the quality ladder for that reason.

OptiX is advanced too. Both OptiX levels run through the same patched ffmpeg build as OIDN. Plain optix is spatial, like OIDN and like everything here except atadenoise; on a grainy source it cut flicker 66% against OIDN's 61%, at about 1.4x OIDN's speed. optix-temporal is the only level that uses motion between frames: it feeds the denoiser the previous denoised frame plus a motion field computed on this GPU's optical-flow engine. Measured, it cut flicker 60% - less than the spatial models, because the noise being removed also corrupts the motion estimate it depends on. It is offered and costed honestly rather than promoted. Neither OptiX level is in the quality ladder.

hqdn3d used to be "Light" and has been retired. It recovered 0.00 dB and 12% of the structural damage - it traded noise for blur one for one. Do not put it back for being cheap.

Off by default: denoise costs roughly 60% of throughput (still about 2.5x realtime at 4K), and on a clean source there is nothing to recover. Worth turning on for a noisy source you are also sharpening: RCAS on a visibly noisy source with no denoise measured a net loss (-0.14 dB, -0.0007 SSIM), because a sharpener amplifies noise as readily as detail.
Master switch. When off, no playback session can turn deblock on.
Not the same job as denoise above. Denoise removes noise in the picture. Deblock removes the SOURCE's own compression damage: the DCT block edges a low-bitrate encode leaves behind, and the mosquito ringing around hard edges. It runs at source resolution, before any super-resolution pass.

It matters because every network here was trained on clean downsampled images. A block edge is not something those networks were ever shown, so they treat it as real detail and reconstruct it - the artefact comes out of the upscale larger and sharper than it went in.

light and strong are libavfilter's deblock filter and address blocking only. fspp and pp7 come from libpostproc and also remove ringing, at more CPU cost. All four are single-threaded CPU passes at source resolution, so they cost more on a large source than on a small one.

Off by default, because no strength has been measured on this content yet.
Master switch. When off, no playback session can turn the refinement pass on.
Not a super-resolution level, and not an alternative to one. It hooks POSTKERNEL, so it runs after the scale and corrects an enlargement rather than producing one - it composes with FSRCNNX, Anime4K, CuNNy, ravu-zoom or plain scaling, and with the unblur pass, instead of replacing any of them.

It is also ratio-agnostic, so unlike the fixed-2x networks it is not skipped below the super-resolution threshold below. That is the reason it is here: between the minimum scale factor and the super-resolution threshold - 720p to 1080p is 1.5x and lands in that band - the chain is otherwise plain scaling plus a sharpener.

Off by default. It costs a pass, and nothing on this server has measured whether it is worth one on this material - which is also why it is not in the player's quality ladder.

The percentages beside these options are one throughput reading each, 854x480 to 1920x1080, 300 frames, on a shared GPU whose encoder capped that run at about 120 fps. They order the options by cost and say nothing at all about how they look.
Master switch. When off, no playback session can turn the chroma pass on.
A different axis from everything else on this page: every other shader here works on the luma plane only. These sources are 4:2:0, so the colour planes are stored at a quarter of the luma resolution and are enlarged by the plain kernel while luma gets a trained network. This hooks CHROMA and reconstructs them using luma as a guide, so it composes with any super-resolution level rather than replacing one.

Off by default, and unmeasured here, for the same reason as the refinement pass above.
Master switch. When off, no playback session can turn a network on.
A separate thing from Detail below, and it is slow. These are ONNX networks run by ONNX Runtime on the CUDA execution provider, through the ort filter in the same separate patched ffmpeg build that carries oidn and optix. They run on the CPU side of the chain before the libplacebo scaling pass, so they compose with whatever Detail shader is selected rather than replacing it.
Measured once each, in the deployed chain, on a 960x540 source at a 1080p target - purely so the cost hint is not invented. With this off: 265 fps. realesr-anime-x2 24 fps (0.56x realtime), realesr-anime-x4 15 fps (0.34x), realesr-general-x4 10 fps (0.24x). None of them sustains realtime for a single session, and all three are about an order of magnitude more expensive than the shader that ships as the default. They are offered because they are worth having available, not because they are better; no quality stage will ever select one.
The weights are not shipped with this plugin. A level whose .onnx file is not present in /usr/lib/jellyfin-ffmpeg-oidn/models is not listed and not offered. See NEURAL.md for how to export them from the official Real-ESRGAN checkpoints. If the patched binary is missing entirely the shim strips the node and the session plays without the network instead of failing.
Master switch. When off, no playback session can turn one on.
Read this before turning one on. These are not image upscalers. FSR2 and DLSS are temporal reconstruction algorithms for a renderer. Everything they gain over a plain resize comes from the renderer handing them exact screen-space motion vectors, a depth buffer, the exact sub-pixel jitter it offset the camera by each frame, and a mask saying where history must not be trusted. A recording contains none of those. Every one is synthesised here: NVOFA optical flow for the motion vectors, a monocular estimate (or a flat plane) for depth, a measured global phase-correlation offset for jitter, and forward/backward flow inconsistency for the mask.
The jitter one cannot be fixed, and it was measured rather than assumed. FSR2's jitter is a single global value; this content's sub-pixel motion is local. The median textured block departs from the global estimate by 0.29 px against FSR2's entire ±0.5 px budget, and AMD's own documentation says the sequence must never produce a null vector - which is exactly what a fixed camera produces. With a near-null sequence the algorithm's locks never sweep the display grid, and what is left is a temporal denoise plus a fixed Lanczos upsample. Expect ghosting, and do not expect super-resolution.
fsr2 and dlss produce the target size themselves, so the Detail shader and the refinement pass are dropped for those two rather than run a second upscaler against the first. dlaa is 1:1 and runs as a restoration pass before the normal scale, so it composes with everything.
Nothing from NVIDIA is shipped with this plugin. dlss and dlaa are listed only when a DLSS runtime (libnvidia-ngx-dlss.so.*, NVIDIA proprietary) has been installed into /usr/lib/jellyfin-ffmpeg-oidn/dlss by hand - see DLSS.md. The monocular depth weights are not shipped either; without them depth falls back to a flat plane. FSR2 itself is MIT and is built from source - see FSR2.md. If the patched binary is missing the shim strips the node and the session plays unenhanced instead of failing.
All four are wrong; they are wrong differently. measured is real but global where the motion is local. halton tells the algorithm sample positions that were never used.
A monocular estimate is relative and renormalised every frame, and the algorithms compare depth across frames to find disocclusion, so an unstable estimate manufactures ghosting. model-stable warps the previous frame's depth by the flow and blends. flat turns every depth-driven decision into a no-op, which is at least a known failure rather than a noisy one. Falls back to flat when the weights are absent or ONNX Runtime has no CUDA execution provider.
The reactive mask is the algorithm's own designed control for ghosting: it marks where history must not be trusted. Flow inconsistency finds occlusion and disocclusion, which is where most of the ghosting comes from. It costs one extra NVOFA pass and does not find transparency or shading change.
libplacebo debanding, with the strength and the grain set below. Measured within run-to-run variance of free. Low-bitrate camera h264 bands visibly in dark gradients, which is what this removes.
How hard debanding cuts. Higher smooths more banding, and more real gradient with it. Default: 3.
Grain added back after debanding. 0 on purpose: libplacebo's own default of 6 dithers synthetic grain over the picture, which is wrong for this content.
libplacebo scaling kernel used underneath the shaders. Default: ewa_lanczos. The list comes from the server, because a kernel name libplacebo does not know fails the whole transcode rather than falling back.

Transcode policy

Which sessions are enhanced, and how they are encoded.

On: upscaling happens only for a session that carried an upscale request, which is what the injected player script sends when a viewer picks a size in the Enhance panel. A session with no such request is transcoded untouched, so clients that do not run the script never spend GPU time. Off: every eligible transcode is upscaled to the target height above, whether or not anybody asked.
Turns a would-be video stream copy into a real transcode so it can be upscaled. Costs GPU time.
Off by default, and read this before turning it on.

When a client can play a file directly, the server never builds an ffmpeg command, so there is nothing to enhance and playback info honestly reports "No enhancement". This setting tells the server to refuse direct play for any item that is eligible for upscaling, which forces a transcode the enhancement chain can run in.

The cost is large and it applies to every client. With this on, direct play effectively stops being used for eligible material, and each of those sessions becomes a GPU transcode subject to the concurrency limit above. Sessions past that limit fall back to stock transcoding, which is more expensive than the direct play they replaced. Leave it off unless you want enhancement everywhere and have the GPU headroom for it.

With it off, the injected player script still forces a transcode for the web player when a viewer picks something in the Enhance menu, so per-session enhancement works either way. This setting is what reaches clients that do not run that script.
Off by default, and read this before turning it on.

Normally the enhanced chain ends with hwdownload,format=yuv420p, moving every output frame from GPU to system memory before NVENC uploads it again for encoding - a full frame's worth of PCIe traffic each way, paid at output size. This setting instead hands NVENC the frame while it is still on the GPU (hwmap=derive_device=cuda), skipping that round trip.

It depends on Vulkan-CUDA interop in the patched ffmpeg build, which has not been confirmed on every server. If sessions fail to start after enabling this, turn it back off; nothing else about the enhancement chain changes.
The video encoder used for any transcode this plugin enhances, including one it forces out of a stream copy. Leave blank or set to auto to follow whatever codec the client negotiated. A named encoder (for example hevc_nvenc or h264_nvenc) is applied only when this ffmpeg build actually has it AND the playback session declared that codec playable; otherwise the negotiated codec is kept, because handing a client a codec it cannot decode is a black screen, not a worse picture. The Recent sessions table below reports which was used and why.

File locations

Where this plugin looks for the files it needs. The defaults suit a standard install, so leave them alone unless you have put something somewhere else.

Where the shader files live. Default: /usr/share/jellyfin-shaders. Point this at a directory without the shaders in it and the levels that need them stop being offered, silently: there is no error, the options simply disappear from this page and from the player.
Where composed shaders are cached. Default: /var/cache/jellyfin/jellyfin-plus-shaders. It must be writable by the user the Jellyfin service runs as.
Where the Real-ESRGAN ONNX weights live. Default: /usr/lib/jellyfin-ffmpeg-oidn/models. The weights are not shipped with this plugin, and a neural level whose file is missing is not offered at all. See NEURAL.md for how to export them from the official Real-ESRGAN checkpoints.
Where the NVIDIA DLSS runtime lives. Default: /usr/lib/jellyfin-ffmpeg-oidn/dlss. It is proprietary and nothing from NVIDIA ships with this plugin, so until you put it here by hand the dlss and dlaa levels are not offered. See DLSS.md for which file is needed and where to get it.
The monocular depth ONNX model the game upscalers are fed instead of a real depth buffer. Default: /usr/lib/jellyfin-ffmpeg-oidn/models/depth_anything_v2_vits.onnx. Not shipped either; without it those levels fall back to a flat plane.
Where nvdlppx.dll lives, for the dlpp-1..dlpp-4 neural levels. Default: /usr/lib/jellyfin-ffmpeg-oidn/rtxdlpp/dll/nvdlppx.dll. Proprietary and nothing from NVIDIA ships with this plugin, so until you put it here by hand these levels are not offered. See RTXDLPP.md.
Where nvaivpx.dll lives, for the vsr-rtcuda neural level - a fast GPU resample, not a network. Default: /usr/lib/jellyfin-ffmpeg-oidn/rtxvsr/dll/nvaivpx.dll. Same rule as above: not shipped, so not offered until installed. See RTXVSR.md.
